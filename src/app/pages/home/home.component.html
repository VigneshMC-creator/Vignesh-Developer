01 / ABOUT

How I approach development.

I like to understand the complete request path before changing a single method.

My day-to-day work is in accounting and bookkeeping software. A change to a transaction workflow can involve the UI, an API endpoint, service logic, data mapping and SQL. I trace those pieces first, especially when existing users depend on behavior that has accumulated over time.

Recent work has involved bringing established functionality into a newer application version, reviewing the previous implementation, updating API flows and checking how data is saved and returned. It has made me pay close attention to backward compatibility, validation and predictable data handling.

I’m strengthening my skills in .NET architecture, EF Core, SQL performance and Angular integration. I use AI-assisted tools as part of development, but I still review, test and make sure I can explain the code I work on.
